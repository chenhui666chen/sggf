# 多供应商视频模型 API 智能路由：落地指导（讨论稿）

> 状态：方案整理，尚未选定供应商、模型和正式接口协议；不是已部署系统的说明。后续根据具体供应商文档、合同及实测数据补全，不据此直接上线收费。

## 1. 目标与边界

向下游平台提供一个稳定的视频生成 API：下游提交生成要求，服务端在多个供应商、同名模型或不同 ComfyUI 工作流中，筛选满足要求的路线，按成本、质量、成功率和交付时间选择与必要时切换。对外隐藏内部路由和上游调用凭证，但**第一阶段直接返回上游成片下载地址**；下载地址可能暴露供应商或对象存储域名，不承诺来源不可识别。文件转存和长期保存由接入平台决定。流式下载代理列入后续规划，不纳入首期交付。

本方案不是单上游 `/v1/chat/completions` 文本透传，也不以“同名模型”作为能力一致的证据；视频接口采用异步任务模式。上游再分发权限、数据处理和面向目标地区提供服务的合规要求，需在商业试运行前逐家核实。

## 2. 已确定的产品原则

1. **一个对外接口，多个内部路线**：同一模型名称下可有不同供应商和工作流，但每条路线独立登记实际能力、版本、价格及质量证据。
2. **先硬筛，再优化**：只在完全满足本次请求的路线中排序和尝试。不得为提高成功率擅自丢弃参考视频、减少参考图片、缩短时长、降低分辨率或改变输入语义。
3. **候选耗尽才判生成失败**：若参考视频只有两条路线支持，按策略尝试这两条；不支持参考视频的路线永远不是备份。无候选属于“能力不支持”，不是“生成失败”。
4. **允许运营成本对冲**：原路线明显慢于其同规格历史基线时，可启动另一条合格路线；原路线此时仍可能成功，重复生成及可能的双重扣费由平台计入运营成本。对外只交付一次、按约定只收一次。
5. **可解释、可复盘**：每个任务留存路由规则、能力/报价快照、每次尝试、上游任务 ID、费用、状态与交付依据。最近 100 条样本仅用于决策窗口，不能代替任务和财务流水。
6. **第一阶段直返上游文件 URL**：明确提醒下游及时下载或自行转存；不保证地址长期有效或不暴露供应商。以后若对域名隐藏有硬性要求，再评估流式下载代理的带宽、鉴权和条款。

## 3. 能力目录与统一请求

内部基本单元是**路线**，即 `供应商 × 模型/工作流 × 版本 × 规格`；不能只记录供应商名称或模型名称。每条路线至少登记：输入模式（文生/图生/参考视频/多图参考等）、素材数量与限制、分辨率与宽高比、可选时长、输出格式、价格与失败扣费/退款规则、上游任务生命周期、可否取消/查重、上游 URL 有效期、当前健康状态、质量验收状态和授权状态。工作流更新视作可追踪的新版本。

对外请求字段需覆盖：生成提示词、参考素材、时长、分辨率/画质档、画幅、可接受费用上限、等待截止时间以及是否允许自动切换或运营对冲。字段、单位、缺省值和错误码暂不锁定，待供应商协议核验后定稿。参考素材建议采用受控上传或下游提供的安全引用；不能让服务端无约束抓取任意传入 URL。

接口形态建议为“提交任务 → 查询任务状态 → 取得结果/上游下载 URL”；回调通知可后加。提交接口返回内部任务 ID，不把上游任务 ID 和 Key 暴露给下游。统一状态最少区分：`accepted / running / delivering / succeeded / failed / unsupported`；内部尝试另行区分提交未知、排队、生成中、上游明确失败、过期、取消和结果校验失败。状态名只是草案，实际以接口契约为准。

请求要求必须同时成立。举例：要求“参考视频 + 10 秒 + ≥1080p”时，只筛选**同时**支持三者的路线，不能把不同供应商各支持的一项拼成一个虚假的候选。

## 4. 两层路由决策

### 4.1 硬条件过滤

先过滤授权未确认/已禁用、能力不足、价格超过客户约束、不能在剩余时限内合理交付、上游配额不可用的路线。没有合格路线，立即返回可解释的“不支持该请求”或“当前无可用路线”，不要先扣生成费用。

同名模型只有在输入语义、输出规格和质量下限满足本次请求时，才进入同一次任务的候选池。质量达标并不意味着所有能力等价；候选池是**针对每次请求动态生成**的。

### 4.2 合格路线排序

先用可解释的规则，而不是黑盒“AI 决策”：质量合格率和交付成功率满足底线的前提下，综合比较预计成功成片成本、近期 P50/P90 耗时、近期故障、排队状态及备用路线独立性。预计成本应纳入明确失败收费、退款、对冲和文件交付开销，而非仅看上游标价。

按 `供应商 × 工作流版本 × 请求类型 × 时长档位 × 分辨率档位` 统计；样本不足时逐级回退到较粗粒度，不要因极少量成功/失败做极端决定。为备用路线留少量探测流量，避免所有请求永远流向一条路线导致备份统计过期。不同供应商可能共用底层渠道，需观察故障是否同步发生。

## 5. 故障切换、慢任务对冲与状态一致性

- **明确提交失败或明确生成失败**：在客户约束允许且有其他合格路线时切换；记录失败原因及是否收费。
- **提交超时/响应丢失**：属于“是否创建成功未知”，不是明确失败。先查询/对账；上游支持幂等键时优先使用。必要时启动备份应显式记录重复扣费风险。
- **已取得上游任务 ID、但超过该路线同规格 P90/P95 基线**：视排队/生成状态及最终截止时间决定是否并行启动另一条合格路线，不直接把原路线记为失败；设置每任务最多并行尝试数和运营成本上限。
- **并行任务陆续完成**：先通过文件及规格验收的结果成为唯一交付结果；其余尝试可取消则取消，否则继续追踪并记录最终状态与实际成本。不得因“抢先失败”把晚完成且成功的路线误记为失败。
- **超过最终截止时间**：按对外约定终止等待并返回明确状态；仍运行的上游任务需要后台跟踪与对账，防止之后成功却漏记费用。

任何一个路线出现问题，不代表其他路线也失败；反过来，不能绕过客户的价格/能力/时限约束无限重试。对外错误至少区分：请求不支持、全部合格路线明确失败、最终超时、上游状态未知、结果下载不可用。

## 6. 指标、熔断与质量抽检

### 6.1 指标定义

分别记录上游任务成功率、真实交付成功率、质量抽检合格率、明确失败率、状态未知率、对冲触发率、对冲重复费用、P50/P90/P95 端到端时间、每个合格成片总成本。不能把“上游返回 success”视作文件可交付，也不能用成片体积或像素数直接代表主观质量。

决策可使用每个细分桶最近约 100 条**已确认状态**的滚动窗口；同时保留必要的全量任务与资金流水以便退款、审计和对账。失败率超过 20% 的路线可自动暂停新任务，但必须先满足最小已完成样本数、持续观察窗口和明确失败定义；少量样本不得触发永久禁用。暂停后用低频探测或人工确认恢复，恢复初期逐步放量。

### 6.2 质量验证

对每条成片做轻量确定性检查：结果链接可访问、文件可下载/解码、时长与分辨率等符合订单要求。这里“链接可访问”并不保证到下游取用时仍有效，须记录上游标示的有效期，并告知下游及时下载。

视觉识别模型**定期分层抽检**：按供应商、工作流与请求类型抽样，比较提示词、参考素材和成片多时刻画面；新路线、恢复路线和投诉异常路线提高抽样比例。对低分样本人工复核，避免把模型偏好误当真实质量；抽检优先用于路由降权、增加采样和供应商复核，不默认阻塞所有订单交付。客户素材传第三方视觉服务前，需核实数据处理约定。

## 7. 下载交付与可见性

首期从上游取得成片 URL 后，将该 URL 作为结果返回下游。优点是不需要代理视频字节或自建存储，也不把下载时间强加到生成任务上；代价是下游能看到下载域名及可能的上游信息，链接可能过期、受鉴权/防盗链限制。必须逐家验证：能否将 URL 分享给下游、链接有效期、是否需要请求头、是否支持跨地域访问、失败时能否重新获取 URL。若 URL 实际不能交付，不能仅凭任务成功就标记“交付成功”。

后续可选流式下载代理：通过自己的下载接口鉴权，服务端从受控的上游任务记录读取文件地址并逐块转给下游，不使用 302/307；若用于播放或断点续传，还需评估 `Range`/206 响应、取消传播、带宽峰值与成本。该方案不负责长期保存，也不能保证绝对不可推断来源；上线前另行评估部署平台的视频分发条款及上游再分发授权。**当前不实施、不作为首期验收项。**

## 8. 收费、风控与运营底线

对外价格应基于能力档位和明确收费条件，不因内部自动切换/对冲而临时增加客户应付费用。至少区分预占额度、最终交付结算、明确失败退款、上游已收费但对外失败的运营损失；流水需幂等且可和上游账单对账。视频生成若收费，不应靠 Workers KV 覆盖写入实现余额或计数。

接入客户需具备身份凭证、模型/能力白名单、请求频率和并发限制、单任务成本上限、客户预算上限；密钥不写入公开配置。对外错误应清洗上游 URL、Key 和内部细节，内部日志按最小必要原则保留。供应商是否允许二次封装并向第三方提供 API，必须得到可留存的书面许可或合同依据；不能以换域名掩盖未获授权的使用。

## 9. 分阶段落地与验收

### 阶段 A：供应商资料核验与实测

选定**一个明确能力档位**和至少两条确实满足该档位的路线。逐家确认授权、能力、错误码、任务查重/取消、成功与失败实际收费、URL 时效；同一批提示词和素材进行对照实测。若仅有一家供应商满足特定能力，则明确标识该能力暂无跨供应商容灾。

### 阶段 B：内部异步路由闭环

完成统一任务创建/查询/结果接口、能力过滤、供应商适配、任务与尝试状态、结果规格校验、上游 URL 返回和费用流水。先人工或固定优先级选择路线；验收“能力不匹配不尝试、明确失败能切换、同一个任务只交付一次”。

### 阶段 C：统计驱动路由与运营对冲

采集同规格滚动指标，先启用可解释的成本/时延/成功率排序，再逐步开放慢任务对冲、熔断与恢复、备用探测、视觉抽检及人工复核。验收“双成功不会双交付、双收费不转嫁客户、状态未知可追踪与对账、低样本不误封”。

### 阶段 D：规模化与下载代理（待选）

在客户确实要求隐藏下载域名、上游条款允许、带宽费用可控的前提下，再实施自己的流式下载接口；是否增设视频存储由下游诉求决定，不默认转存所有文件。

## 10. 已知示例与不可推断项

以下只是单次测量样本，不能直接作为真实售价、长期成功率或熔断阈值依据：`lightx2v_no_pic` 480p/5s 约 ¥1.50、102s；`zm_u08` 768p/5s 约 ¥2、170.5s；`zm_u24` 768p/5s 约 ¥2、169.9s；`z0901` 1440p/5s 约 ¥4、291s；`lightx2v_v5` 多图参考 1080p/10s 约 ¥9、1268s。它们属于不同能力/规格，不得全部放进单个无差别备选池。`Minimax-H3` 等相同名称也不证明提供商底层模型、调用路径与质量完全相同。

此前讨论的候选来源：TTapi（lsgyl.xyz）、算力AI（suanliai.top）、Grsai（grsai.ai）、n1n.ai（api.n1n.ai）、DMXAPI（dmxapi.cn）。它们目前仅为候选网站，不代表已经核实转售授权、能力、价格或可用性；本稿不承诺接入任何一家。

## 11. 后续供应商/模型资料交接清单

请为每家候选供应商、每条拟接入的模型或 ComfyUI 工作流提供或标记未知：

- 正式名称、合同/许可主体、二次封装与下游调用授权范围、测试与商用限制；
- 官方文档 URL、Base URL、鉴权方式、接口版本、请求/查询/取消与回调示例、错误码；
- 真实模型 ID 与工作流 ID/版本、支持的输入类型、素材上限、时长、分辨率、画幅、输出格式；
- 各规格单价、实际扣费样例、失败/审核失败/取消/超时是否退款、价格更新时间及变更通知方式；
- 上游任务 ID、状态含义、幂等/查询提交结果能力、排队与生成时长样本、限速/并发上限；
- 文件 URL 样例（先脱敏）、有效期、是否可分享给下游、下载鉴权/防盗链、能否重取、版权/水印与元数据；
- 相同测试集的实际成功率、质量抽检与人工验收结果、输出像素与时长、各环节延迟；
- 数据保存、日志、地域、敏感内容及合同要求；客户的预计请求规模与目标能力档位。

收到具体供应商及模型名单后，先制作逐路线能力/成本/失败语义对照表，明确哪些**在某类请求下**可互为备份，再完善统一字段映射、报价、路由策略、状态机与验收用例。所有未有证据的字段标为“待核验”，不以平台宣传或相似模型名代替实际测试。
