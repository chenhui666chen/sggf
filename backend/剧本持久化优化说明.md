# 剧本持久化优化说明

## 问题背景

**用户痛点**：
- 用户在剧本编辑页面修改音色配置后，如果重新生成音频，剧本会被覆盖
- 必须重新跑一遍剧本生成阶段，非常耗时

**期望行为**：
- 剧本编辑页面的数据应该持久化更长时间
- 只有在"下次新剧本生成"时才覆盖已有剧本
- 修改音色后，可以直接基于已有剧本生成音频

## 解决方案

### 1. 剧本状态管理

引入三种剧本状态来控制覆盖行为：

```python
script_status:
  - "pending"   : 待审核（可被覆盖）
  - "reviewed"  : 已审核（受保护，不覆盖）
  - "approved"  : 已通过（受保护，不覆盖）
```

### 2. 持久化保护逻辑

**剧本生成阶段** (`generate_audiobook_scripts_background`)：

```python
# 🆕 持久化优化：检查是否已有剧本
if chapter_audio and chapter_audio.script_json and not force_regenerate:
    if chapter_audio.script_status in ["reviewed", "approved"]:
        # 已审核/通过的剧本受保护，跳过生成
        logger.info(f"✅ [跳过] 章节 {chapter_id} 已有{chapter_audio.script_status}剧本，保持不变")
        continue
    else:
        # pending状态的剧本可以覆盖
        logger.info(f"🔄 [覆盖] 章节 {chapter_id} 剧本状态为{chapter_audio.script_status}，将重新生成")
```

### 3. 强制重新生成机制

新增 `force_regenerate_script` 参数，支持用户主动覆盖：

```python
# API请求示例
POST /api/v1/audiobook/projects
{
  "project_id": 1,
  "chapter_ids": [1, 2, 3],
  "generation_mode": "script_only",
  "force_regenerate_script": true  // 🆕 强制重新生成剧本
}
```

## 使用场景

### 场景1：首次生成剧本

```python
# 1. 创建有声书项目（仅生成剧本）
POST /api/v1/audiobook/projects
{
  "generation_mode": "script_only",
  "chapter_ids": [1, 2, 3]
}

# 剧本自动设置为 script_status="pending"
```

### 场景2：修改音色后生成音频

```python
# 2. 用户在前端修改了某个角色的音色配置（如苏娜改为女声）

# 3. 直接触发音频生成（不重新生成剧本）
POST /api/v1/audiobook/projects/{id}/generate-audio-from-scripts
{
  "chapter_ids": [1, 2, 3]
}

# ✅ 已有剧本被保留，只重新合成音频
```

### 场景3：手动编辑剧本后生成音频

```python
# 1. 用户手动编辑剧本片段
PUT /api/v1/audiobook/projects/{id}/chapters/1/script
{
  "script_segments": [...],
  "script_status": "approved"  // 标记为已通过
}

# 2. 再次触发剧本生成（其他章节）
POST /api/v1/audiobook/projects
{
  "generation_mode": "script_only",
  "chapter_ids": [1, 2, 3]
}

# ✅ 章节1的剧本被跳过（已approved），章节2、3重新生成
```

### 场景4：强制重新生成剧本

```python
# 用户对原剧本不满意，想重新生成
POST /api/v1/audiobook/projects
{
  "generation_mode": "script_only",
  "chapter_ids": [1, 2, 3],
  "force_regenerate_script": true  // 🔥 强制覆盖
}

# ✅ 即使剧本状态为approved，也会被覆盖
```

## 技术实现

### 修改的文件

1. **`backend/app/schemas/audiobook.py`**
   - 新增 `AudiobookProjectCreate.force_regenerate_script` 参数

2. **`backend/app/api/v1/audiobook.py`**
   - 修改 `generate_audiobook_scripts_background` 函数
   - 新增持久化保护逻辑
   - 支持强制重新生成参数

### 数据库字段

使用已有字段 `ChapterAudio.script_status`：

```sql
-- 剧本状态（用于控制覆盖行为）
script_status VARCHAR(20) DEFAULT 'pending'
  -- 'pending': 待审核（可被覆盖）
  -- 'reviewed': 已审核（受保护）
  -- 'approved': 已通过（受保护）
```

## 优势

✅ **避免重复工作**：修改音色后不需要重新生成剧本，节省大量时间  
✅ **保护用户编辑**：已审核/编辑的剧本不会被意外覆盖  
✅ **灵活控制**：用户可以通过 `force_regenerate_script` 主动覆盖  
✅ **向后兼容**：默认行为与旧版本一致（pending状态剧本可覆盖）

## 前端集成建议

前端可以根据 `script_status` 显示不同的状态标识：

```javascript
// 剧本编辑页面
function ScriptEditor({ chapter }) {
  const statusBadge = {
    pending: "待审核",
    reviewed: "已审核 🔒",
    approved: "已通过 ✅"
  }[chapter.script_status];

  return (
    <div>
      <Badge>{statusBadge}</Badge>
      {/* 剧本编辑器 */}
      <Button onClick={approveScript}>批准剧本</Button>
    </div>
  );
}
```
