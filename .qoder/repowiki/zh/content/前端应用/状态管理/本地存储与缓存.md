## 简介
本技术文档聚焦小说创作代理系统的“本地存储与缓存机制”，围绕以下目标展开：
- IndexedDB 的使用模式：数据存储、查询优化与事务处理
- 本地资产库设计：文件管理、元数据保存与版本控制
- 数据迁移策略：版本升级、数据结构变更与数据完整性保证
- 本地恢复机制：数据备份、故障恢复与冲突解决
- 缓存策略设计：LRU 缓存、过期策略与内存管理
- 数据安全、隐私保护与性能优化方案

本系统在前端使用浏览器本地存储（IndexedDB）进行用户资产与缓存，后端通过服务层提供缓存系统与数据库兼容性适配，并通过 API 暴露资产相关能力。

## 核心组件
- 前端本地存储封装（IndexedDB）
  - 负责打开/创建对象存储、读写事务、索引构建、批量操作与错误回滚
  - 提供统一的键空间与命名约定，避免跨功能冲突
- 前端本地缓存 Hook
  - 封装 LRU 策略、过期时间、内存上限与自动淘汰
  - 与 IndexedDB 协同，热路径走内存，冷路径落盘
- 后端缓存服务
  - 提供进程内缓存、TTL 过期、命中率统计与降级策略
  - 与数据库查询解耦，支持按业务域隔离
- 资产库模块（前后端）
  - 统一资产标识、元数据模型、版本化与引用计数
  - 文件分片、去重、校验与懒加载
- Schema 兼容层
  - 向后兼容旧字段、增量迁移、缺失字段默认值填充
- 资产 API
  - 对外暴露资产上传、检索、版本切换与同步接口
- 契约与脚本
  - 自动生成前端本地存储元数据契约，确保前后端一致

## 详细组件分析

### IndexedDB 使用模式（前端）
- 存储设计
  - 对象存储按业务域划分（如 userAssets、metaIndex、chunks），每个对象存储包含必要索引（如 assetId、version、createdAt）
  - 二进制大对象（图片/音频片段）采用分块存储与元数据分离，减少单条记录体积
- 查询优化
  - 复合索引用于常见过滤条件（如 projectScope + type + status）
  - 游标分页与范围查询结合，避免全表扫描
- 事务处理
  - 写操作使用显式事务，失败时回滚；读操作使用只读事务提升并发
  - 批量写入采用事务合并，降低磁盘抖动

```mermaid
flowchart TD
Start(["开始"]) --> OpenDB["打开/创建IndexedDB"]
OpenDB --> CheckStore{"对象存储是否存在?"}
CheckStore --> |否| CreateStore["创建对象存储与索引"]
CheckStore --> |是| ReadWrite{"读/写操作?"}
CreateStore --> ReadWrite
ReadWrite --> |读| BeginReadTx["开启只读事务"]
ReadWrite --> |写| BeginWriteTx["开启读写事务"]
BeginReadTx --> ExecQuery["执行查询/游标遍历"]
ExecQuery --> EndReadTx["提交只读事务"]
BeginWriteTx --> ExecBatch["批量写入/更新"]
ExecBatch --> ValidateData["校验数据完整性"]
ValidateData --> CommitTx["提交事务"]
CommitTx --> EndWriteTx["结束事务"]
EndReadTx --> Done(["完成"])
EndWriteTx --> Done
```

### 本地缓存策略（前端）
- LRU 缓存
  - 基于访问顺序维护最近最少使用队列，达到容量上限时淘汰最久未使用的条目
- 过期策略
  - 每条缓存附带 TTL，读取时检查是否过期，过期则删除并触发回填
- 内存管理
  - 限制最大条目数与单条大小，避免内存溢出
  - 定期清理过期项与碎片

### 数据迁移策略（后端）
- 版本升级
  - 通过 Schema 兼容层检测当前版本与目标版本，逐步应用迁移步骤
- 数据结构变更
  - 新增字段设置默认值，废弃字段标记为可选，保持向前兼容
- 数据完整性保证
  - 迁移前校验关键约束，迁移中记录日志，失败时回滚或修复

```mermaid
flowchart TD

Compare --> |否| Skip["跳过迁移"]

PlanSteps --> Validate["校验数据完整性"]

NextStep --> |是| ApplyStep
NextStep --> |否| Finalize["提交并更新版本"]

```
