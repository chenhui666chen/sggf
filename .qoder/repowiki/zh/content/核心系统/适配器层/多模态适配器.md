## 简介
本技术文档面向“多模态适配器”子系统，系统性阐述文本、图像、音频、视频等多类型输入输出的适配实现方式。重点覆盖：
- 跨模态数据处理与格式转换
- 内容理解与统一抽象
- 多模态任务编排策略、结果融合与一致性保证
- 复杂业务场景下的适配器组合模式与错误处理
- 完整工作流示例与性能优化技巧
- 自定义多模态适配器的开发指南与测试方法

## 项目结构
多模态适配器位于 adapters 目录，按提供商（如 dashscope、volcengine）与能力（image、tts、video、multimodal）组织；核心运行时与调度在 core 目录；统一规范与契约在 schemas 目录；上层编排由后端服务与代理协调器驱动。

## 核心组件
- 适配器基类与注册表
  - 提供统一的接口抽象、能力声明、参数校验与结果规范化
  - 集中注册各厂商/能力的适配器，支持按模型ID或能力路由
- 媒体与LLM统一运行时
  - 统一封装图像、音频、视频、文本等媒体的加载、编码、解码与传输
  - 统一LLM调用入口，屏蔽不同模型的请求差异
- 模型目录与解析
  - 维护模型元数据、能力矩阵与版本信息
  - 根据任务规格选择合适模型与适配器
- 编排与执行引擎
  - 将多模态任务分解为步骤，管理并发、重试、回退与结果融合
- Mock适配器
  - 用于开发与测试阶段的快速验证与回归

## 架构总览
多模态适配器采用“统一接口 + 注册路由 + 运行时封装 + 编排引擎”的分层架构。上层通过统一运行时发起任务，运行时依据模型目录与解析策略选择具体适配器，适配器负责与外部模型交互并返回标准化结果。

```mermaid
sequenceDiagram
participant Client as "客户端/服务"
participant Agent as "代理协调器"
participant Exec as "执行引擎"
participant Reg as "适配器注册表"
participant Res as "模型解析/目录"
participant UM as "统一媒体运行时"
participant LLM as "统一LLM客户端"
participant Adapter as "具体适配器"
Client->>Agent : 提交多模态任务
Agent->>Exec : 构建任务计划
Exec->>Res : 查询模型能力与版本
Res-->>Exec : 候选模型列表
Exec->>Reg : 按能力/模型ID获取适配器
Reg-->>Exec : 适配器实例
Exec->>UM : 准备输入媒体(文本/图/音/视)
UM-->>Exec : 标准化输入
Exec->>Adapter : 调用适配器接口
Adapter->>LLM : 构造请求并发送
LLM-->>Adapter : 原始响应
Adapter-->>Exec : 标准化输出
Exec->>Exec : 结果融合/一致性校验
Exec-->>Agent : 聚合结果
Agent-->>Client : 返回最终产物
```

- 基类职责
  - 定义统一的能力描述、输入输出规范、参数校验与错误映射

  - 维护能力到适配器的映射，支持按模型ID、能力标签、版本进行查找

### 统一媒体运行时与LLM客户端
- 统一媒体运行时
  - 负责图像、音频、视频的编解码、尺寸/采样率调整、缓存与IO优化
  - 提供内存与磁盘的混合存储策略，减少大对象拷贝
- 统一LLM客户端
  - 封装HTTP/WebSocket/流式接口，统一鉴权、重试、超时与错误码映射
  - 支持文本、图像、音频、视频的多模态请求构造


  - 将多模态任务拆分为子任务（如先文本生成提示词，再图像生成，最后视频合成）

  - 合并多个子任务的输出，进行语义一致性与时序对齐检查

## 故障排查指南
- 常见问题定位
  - 模型不可用或能力不匹配：检查模型目录与能力矩阵
  - 媒体格式不支持：确认统一媒体运行时的预处理链
  - 超时与限流：查看重试策略与限流器配置
  - 结果不一致：检查一致性校验规则与融合逻辑
- 调试建议
  - 启用详细日志与追踪，记录请求/响应摘要
