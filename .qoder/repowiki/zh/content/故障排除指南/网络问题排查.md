## 简介
本指南面向网络相关问题的系统化排查与优化，覆盖以下典型场景：
- HTTP API 调用失败（连接超时、SSL 证书问题、认证失败）
- WebSocket 连接断开（心跳检测、重连机制、消息丢失）
- 第三方 AI 服务集成问题（API 限流、响应超时、数据格式不匹配）
同时提供网络抓包与调试工具使用建议（curl、Wireshark、浏览器开发者工具），并给出代理配置、负载均衡、故障转移的排查方法，以及网络延迟优化与连接池调优建议。

## 项目结构
本项目采用前后端分离与多适配器架构：
- 后端 FastAPI 应用入口与路由位于 backend/app
- 模型与第三方服务通过 adapters 层统一封装
- 统一的 LLM 客户端与运行时管理位于 core 层
- WebSocket 管理与流式服务位于 backend/app/websocket 与 services
- Nginx 作为反向代理与负载均衡器
- Docker Compose 编排服务与依赖


### WebSocket 管理器（心跳与重连）
- 职责：维护长连接、心跳检测、断线自动重连、消息顺序保证与丢失恢复
- 关键能力：
  - 心跳间隔与超时阈值
  - 指数退避重连与最大重试次数
  - 未确认消息队列与重发
  - 连接状态监控与告警

```mermaid
flowchart TD
Start(["WS 连接建立"]) --> Heartbeat["启动心跳定时器"]
Heartbeat --> CheckAlive{"收到心跳?"}
CheckAlive --> |否| Reconnect["触发重连(指数退避)"]
CheckAlive --> |是| ProcessMsg["处理消息/ACK"]
ProcessMsg --> QueueCheck{"有未确认消息?"}
QueueCheck --> |是| Resend["重发未确认消息"]
QueueCheck --> |否| KeepAlive["保持连接"]
Reconnect --> Verify{"重连成功?"}
Verify --> |否| Backoff["等待后重试"]
Verify --> |是| Resume["恢复会话/重放队列"]
Resume --> KeepAlive
Backoff --> Reconnect
```

## 性能考量
- 连接池调优：根据并发与上游 QPS 调整最大连接数、空闲回收时间，避免连接耗尽与频繁握手
- 超时与重试：合理设置连接/读写超时，配合指数退避与熔断，降低雪崩风险
- 流式传输：优先使用流式接口减少内存占用与首字节延迟
- 代理与缓存：在 Nginx 层启用合适的缓冲与缓存策略，减轻后端压力
- 心跳与重连：缩短心跳间隔但避免过多开销，重连采用指数退避与上限控制

## 故障排查指南

### HTTP API 调用失败（连接超时、SSL 证书问题、认证失败）
- 连接超时
  - 检查 Nginx 代理超时与后端服务响应时间
  - 查看统一 LLM 客户端超时配置与重试策略
  - 使用 curl 验证连通性与延迟
- SSL 证书问题
  - 校验证书链与有效期，确认证书自动续期正常
  - 检查系统 CA 信任库与中间证书
  - 使用 openssl 与浏览器开发者工具查看握手细节
- 认证失败
  - 核对 Token/密钥与签名算法
  - 检查代理鉴权与网关白名单
  - 查看适配器错误映射与日志

```mermaid
flowchart TD
Start(["HTTP 调用失败"]) --> CheckTimeout["检查超时配置"]
CheckTimeout --> TimeoutOK{"是否超时?"}
TimeoutOK --> |是| TuneTimeout["调整超时/重试"]
TimeoutOK --> |否| CheckSSL["检查SSL证书"]
CheckSSL --> SSLOK{"证书有效?"}
SSLOK --> |否| FixSSL["更新证书/信任链"]
SSLOK --> |是| CheckAuth["检查认证信息"]
CheckAuth --> AuthOK{"认证成功?"}
AuthOK --> |否| FixAuth["修正Token/签名"]
AuthOK --> |是| Probe["使用curl/Wireshark抓包"]
Probe --> End(["定位根因"])
```

### WebSocket 连接断开（心跳检测、重连机制、消息丢失）
- 心跳检测
  - 确认心跳间隔与超时阈值合理
  - 观察心跳报文是否被代理或防火墙拦截
- 重连机制
  - 检查指数退避与最大重试次数
  - 确保会话上下文恢复与未确认消息重放
- 消息丢失
  - 引入 ACK 机制与去重
  - 记录消息序列号与消费位点

### 第三方 AI 服务集成问题（API 限流、响应超时、数据格式不匹配）
- API 限流
  - 启用令牌桶或滑动窗口限流
  - 观察 429 错误与退避策略
- 响应超时
  - 调整客户端与服务端超时
  - 使用流式接口降低长耗时影响
- 数据格式不匹配
  - 校验请求/响应 Schema
  - 增加字段兼容与降级逻辑
