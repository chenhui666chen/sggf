本项目采用基于 Docker Compose 的全栈容器化构建与部署方案，前后端分离、统一通过 Nginx 反向代理对外暴露。后端使用 Python 3.11 + FastAPI + Uvicorn，前端使用 Node 18 + Vite + React，数据库为 PostgreSQL 15，缓存/任务队列使用 Redis 7 + Celery。

**构建系统组成**
- 后端镜像：`backend/Dockerfile` 基于 `python:3.11-slim`，安装 ffmpeg、postgresql-client 等系统依赖，使用阿里云 Pypi 镜像源加速依赖安装，启动命令为 `uvicorn app.main:app --host 0.0.0.0 --port 8000`。
- 前端镜像：`frontend/Dockerfile` 采用多阶段构建（Node 18 Alpine 构建 → Nginx 静态托管），通过 `VITE_API_URL`、`VITE_WS_URL`、`VITE_APP_NAME`、`VITE_APP_VERSION` 等构建参数注入运行时配置。
- 编排文件：根目录 `docker-compose.yml` 定义 postgres、redis、backend、frontend、nginx 五个服务，包含健康检查、卷挂载、环境变量、资源限制与网络隔离。
- Nginx 反向代理：`nginx-prod.conf` 提供 HTTPS 终止、Gzip 压缩、安全头、WebSocket 长连接代理、静态资源缓存与健康检查路由 `/health`。

**依赖管理策略**
- 后端依赖通过 `backend/requirements.txt` 锁定版本（FastAPI 0.104.1、Uvicorn 0.24.0、SQLAlchemy>=2.0.23、Celery 5.3.4 等）。
- 前端依赖通过 `frontend/package.json` 管理，使用 `npm ci` 确保可重复构建。
- 契约测试依赖独立维护于 `backend/requirements-contract.txt`，由 GitHub Actions 单独安装。

**CI/CD 流水线**
- `.github/workflows/contracts.yml` 在 push/PR 到特定路径时触发，执行 Python 3.11 + Node 20 环境下的契约校验：生成派生类型、运行 pytest 契约测试、运行 Vitest 前端契约测试与 TypeScript 类型检查。
- 无通用 build/test/lint 流水线，仅针对跨端数据契约进行自动化验证。

**本地开发脚本**
- `start_production.bat`：一键检查 Docker 环境、停止旧服务、清理容器、构建镜像、启动所有服务并执行健康检查（PostgreSQL、Redis、Backend、Frontend、Nginx）。
- `deploy_unified.bat`：统一部署入口，委托给 `deploy_sync_improved.ps1` 执行远程同步部署。
- `dev.bat`、`install.bat`、`dev-kill.ps1` 等辅助脚本用于开发环境生命周期管理。

**数据库迁移**
- 使用 Alembic 管理迁移，配置文件 `alembic.ini`，迁移脚本位于 `backend/alembic/versions/`，按功能模块命名（如 `add_chapter_audio_runs.py`、`merge_heads.py` 等）。
- 数据库初始化脚本位于 `postgres-init/01-init.sql`，通过 Docker Compose 的 `/docker-entrypoint-initdb.d` 自动执行。

**环境与配置**
- 环境变量集中通过 `docker-compose.yml` 的 `environment` 字段注入，包括数据库连接、Redis 密码、JWT 密钥、CORS 白名单、OSS 存储配置等。
- 支持 `.env` 文件覆盖敏感配置（如 OSS 访问密钥），并通过 `${VAR:-default}` 语法提供默认值。
- SSL 证书通过 `ssl/cert.pem` 和 `ssl/key.pem` 挂载，支持 Let's Encrypt 自动续期。

**约束与约定**
- 后端必须暴露 `/health` 健康检查接口供启动脚本验证。
- 前端构建产物必须输出到 `dist/` 目录，由 Nginx 静态托管。
- 所有外部依赖必须在对应 `requirements.txt` / `package.json` 中声明，禁止隐式依赖。
- 跨端数据契约变更必须同步更新派生代码并通过 CI 契约校验。
