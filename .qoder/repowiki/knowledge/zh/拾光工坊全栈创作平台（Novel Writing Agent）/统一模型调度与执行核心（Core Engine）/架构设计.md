模块以 `core/__init__.py` 为对外统一入口，按职责划分为若干子层：
- 配置层：`config.py` 通过 dataclass 聚合 Router/Fallback/Execution/Registry/Adapter/TaskSpec 等常量，`logging_config.py` 提供统一 logger。
- 注册与适配层：`unified_registry.py` 实现单例 `UnifiedModelRegistry`，维护 UnifiedModelSpec、BaseLLMAdapter 抽象、性能统计与熔断器；`llm_adapters.py` 基于 OpenAI 兼容协议实现多个厂商适配器，并通过 `@register_llm_model` 装饰器自动注册。
- 路由与评分层：`router.py` 的 `SmartRouter` + `CapabilityFilter`/`ModelScorer`/`LoadBalancer` 完成能力过滤、多维度打分与负载均衡，并可选接入 `semantic_matcher.py` 做语义 boost。
- 执行编排层：`execution_engine.py` 的 `ExecutionEngine` 通过线程池+超时包装 `execute`/`execute_batch`，失败时委托 `fallback_manager.py` 的 `FallbackManager` 执行降级链与任务参数退化。
- 高层门面：`model_hub.py` 的 `ModelHub` 是异步主入口，封装 resolve_model_request、重试退避、内容安全回退链与 catalog 守卫重定向；`unified_llm_client.py` 和 `langchain_bridge.py` 分别提供同步/异步客户端与 LangChain BaseChatModel 桥接。
- 多模态扩展：`unified_media_runtime.py` 面向图像/视频/TTS 操作，复用 registry 与策略权重体系；`model_resolution.py` 集中 TaskType 枚举与别名归一化。
- 辅助工具：`validators.py` 校验 TaskSpec 约束，`model_catalog_runtime.py` 提供运行时目录索引，`mappers/` 与 `telemetry/` 为字段映射与遥测预留。
依赖方向自下而上：adapters → registry → router/fallback → execution → model_hub → client/bridge，各层通过 dataclass/enum 解耦，避免循环导入。
