模块以 `state_machine.py` 中的 `State` 枚举和 `step()`/`run_until_done()` 为核心，驱动从 SCRIPT → STORYBOARD → ASSET_LIBRARY → KEYFRAMES → MIDFRAMES → VIDEO → EDIT → REVIEW → DONE/REWORK/FAILED 的完整流程；每个阶段通过 `with _stage_timer(...)` 包裹对应 agent 调用并记录遥测。

- 入口与对外 API：`autoqc.py` 仅做 re-export，真正入口在 `autoqc_pkg/__init__.py`，由 `_run.run(payload)` 聚合语义质检、状态连续性检查、镜头衔接检查、视频片段 QC 等子模块。
- AutoQC 子系统（`autoqc_pkg/`）：采用数据类（`_dataclasses.py`）+ 策略规划（`_semantic_checks.py`、`_state_checks.py`）+ 评分器（`_scoring.py`）+ 路由决策（`_routing.py`）的分层设计，通过 `_run_helpers.py` 统一调度 VLM adapter、预算分配与各轮检查。
- 运行时支撑：`smart_tuning.py` 根据 quality_mode/shot_count/source_len 动态调整 image_config 与 qc_config；`restart_reset.py` 按 start_state + reset_policy 清理下游产物并支持按 cam_idx/shot_id 局部重跑；`dreamweaver_smart_dispatch_trace.py` 在每个阶段后写入 `smart_dispatch_trace` 结构，记录模型选择、提示词变更与回退链。
- 基础设施：`artifacts_io.py` 提供带重试与原子落盘的 URL 下载；`ffmpeg_runner.py` 封装 ffmpeg 子进程调用并将失败日志落盘；`media_presets.py`、`style_presets.py`、`library_regenerate_roles.py` 提供媒体规格、风格预设与角色视角解析等常量与归一化工具；`step_budget.py` 基于环境变量估算最大步数。
- 依赖方向：state_machine 依赖 agents.*（planner/scripter/storyboarder/painter/editor/auditor/dreamweaver/asset_library）与 pipeline 内各辅助模块；autoqc_pkg 不反向依赖 state_machine，仅消费 payload Dict。
